# ジャンル別の編成推論

この資料は、ジャンル名から楽器編成を決め打ちするための一覧ではない。会話中のStyle、Lyrics、指定楽器、ムード、生成後の症状から、複数の編成仮説を作るための事前分布である。

## 選定方針

対象は、世界的な聴取調査で上位に挙がるジャンル、地域的に強いジャンル、SunoコミュニティでStyle語として頻出するジャンルファミリーとした。これは厳密な人気ランキングでも完全なジャンル一覧でもない。IFPIはPop、Rock、Hip-Hop/Rap、Dance/Electronic、Latin、R&B、Classical/Opera、Countryなどを世界の上位ジャンルとして示し、日本のJ-rock・J-pop、K-pop、City Popなどの地域ジャンルも示している。Spotifyの2025年動向はPop、K-pop、Country、Afrobeats、Rockなどの伸長や再注目を報告している。SunoコミュニティのStyleガイドは、Pop、Rock、Rap、Metal、Electronic、R&B、Country、Jazz、Funk、J-pop、K-popなどを頻出語として扱っている。

## 未収載ジャンルの扱い

この資料にないジャンル、地域ジャンル、細分化されたサブジャンル、フュージョンを、最も近い項目へ機械的に押し込まない。必要なら次の順で追加調査する。

1. ジャンル名の一般的な定義と典型編成を、音楽教育資料・信頼できる解説・一次資料で確認する。
2. そのジャンルで音域や厚みに関係する役割を、楽器・奏法・リズム・音色に分解する。
3. SunoでのStyle表現や生成傾向は、公式情報とユーザー観測を分けて確認する。
4. 根拠が足りなければ、断定せず複数仮説としてユーザーに提示する。

事前整理の目的は網羅ではなく、頻出ケースで毎回ゼロから調べないことにある。未知のジャンルを調査できるなら、未収載であること自体は回答の障害にしない。

## 使い方

1. まずユーザーが明示した楽器・奏法・編成を抽出する。
2. Styleにある全体指定を優先し、Lyricsのタグや局所cueはセクション限定の補助情報として扱う。タグの公式性は別途確認する。
3. ジャンル名から`genre-arrangements.json`の該当ファミリーを引き、明示情報と矛盾しないvariantだけを候補にする。
4. 生成後の症状を音楽的役割へ変換する。例: 中域不足ならギター、声、スネア、鍵盤/パッド、低音不足ならベース、キック、タム、低中域ギター、サブベースを候補にする。
5. 最も確からしい案を1つに決め打ちせず、通常2〜4案を提示する。各案には狙い、前に出す楽器、Style断片、向いているケースを付ける。
6. ユーザーが選択した後、選ばれたvariantのStyle語彙を使って最終案を作る。どれでもない場合は、追加の楽器・ボーカル・自然なバンド音か電子補強かだけを質問する。

## 既存入力による上書き

ジャンルの一般論より、ユーザーの具体的な指示を優先する。

- `electric piano` がStyleにあるなら、Popの中域候補として電気ピアノを採用する。
- `clean arpeggiated guitar` が明示されているなら、ギター中心案を優先し、シンセ追加は別案として扱う。
- Lyricsに`[Guitar Solo]`があっても、それだけで全編ギター中心とは断定しない。公式固定タグかどうか、配置、他の指示を確認する。
- `no synth`のような除外意図がある場合、シンセ補強を標準案にしない。Exclude Stylesが使える画面でも、短い除外語とStyleの肯定形を分ける。

## 編成知識の確度

- 楽器の意味、奏法、音域、典型的な役割は音楽教育資料で確認できる「音楽意味論」として扱う。
- 「そのStyle語を入れればSunoがその楽器を出す」「このジャンルなら必ずこの編成になる」は保証せず、Suno効果は暫定仮説とする。
- `midrange`、`deep bass`、`full-bodied`などの抽象語だけで回答を終えず、楽器・奏法・役割を併記する。
- 編成が複雑なジャンルでは、候補を全部一つのStyleに詰め込まず、主役1〜2個と土台を選ぶ。

詳細な候補は [genre-arrangements.json](genre-arrangements.json) を参照し、音域症状の会話テンプレートは [arrangement-diagnosis.md](arrangement-diagnosis.md) を使う。
